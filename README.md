# Расписание занятий факультета

## Описание проекта
Консольное приложение для управления расписанием учебных занятий на факультете.
Программа позволяет составлять расписание, проверять конфликты (аудитории, преподаватели, группы),
считать нагрузку преподавателей и искать свободные окна.

## Архитектура проекта (Пакеты)
Проект разделен на слои, чтобы код был чистым и расширяемым:

*   **`model`** — содержит сущности предметной области:
    *   `Audience` (Аудитория) — корпус, номер, вместимость.
    *   `Teacher` (Преподаватель) — табельный номер, ФИО.
    *   `Group` (Группа) — код группы, количество студентов.
    *   `Discipline` (Дисциплина) — код и название (реализован как `record`).
    *   `PairNumber` (Номер пары) — перечисление с временем начала и конца.
    *   `WeekDay` (День недели) и `WeekParity` (Четность недели).
    *   `Lesson` (Занятие) — **sealed-интерфейс**, разрешающий только три типа:
        *   `Lecture` (Лекция) — для потока из нескольких групп.
        *   `Practice` (Практика) — для одной группы.
        *   `Lab` (Лабораторная) — для подгруппы.
    *   `ScheduleEntry` (Запись расписания) — связка «День + Занятие + Аудитория».

*   **`exception`** — кастомные исключения:
    *   `ValidationException` — ошибка некорректных данных (например, аудитория слишком мала).
    *   `ScheduleConflictException` — ошибка конфликта (аудитория, преподаватель или группа заняты).

*   **`service`** — логика:
    *   `Schedule` — главный сервис. Умеет добавлять занятия с проверкой конфликтов,
        выводить расписание по группе/преподавателю/аудитории, считать нагрузку в часах,
        строить расписание на диапазон дат и искать свободные окна.

*   **`demo`** — демонстрация:
    *   `Main` — консольное приложение, которое создает объекты, вызывает методы сервиса
        и показывает все операции базового и повышенного уровня.

*   **Тестирование (папка `src/test/java`)**:
    *   `ru.faculty.schedule.ScheduleTest` — набор из 14 тестов на JUnit 5.
        Проверяет корректность работы `equals/hashCode`, граничные случаи
        и выброс кастомных исключений (`ScheduleConflictException`, `ValidationException`).

## Технологии
*   **Java 21** (используются `record`, `sealed interface`, pattern matching для `switch`, `var`).
*   **Maven** (сборка проекта).
*   **JUnit 5** (14 сценариев тестирования, включая граничные случаи и проверку исключений).

## Команда запуска
1. Убедитесь, что установлена Java 21.
2. Откройте проект в IntelliJ IDEA.
3. Запустите класс `demo.Main` (нажмите зеленую стрелочку рядом с методом `main`).

## Запуск тестов
1. Откройте класс `ru.faculty.schedule.ScheduleTest`.
2. Нажмите зеленую стрелочку рядом с названием класса (Run 'ScheduleTest').
    *   Все 14 тестов должны быть зелеными.
